# Colab image worker

Run `serve_image_api.ipynb` on the reviewed Python 3.12/T4 Colab runtime. The notebook requires an audited `aiflow-image-worker.zip` containing this package, `requirements-lock.txt`, and `audit-approval.json`. Package installation fails unless approval is true and its `requirements_sha256` matches the lock bytes; pip uses pinned wheel hashes, no dependency resolution or source builds. No code executes from Drive.

The approved local model snapshot is RealVisXL V5 fp16 plus general IP-Adapter Plus SDXL ViT-H, suitable for reference portraits of humans or pets. The default sampler is official Diffusers DPM++ 2M Karras (`DPMSolverMultistepScheduler`, `algorithm_type=dpmsolver++`, `solver_order=2`, `use_karras_sigmas=True`, `thresholding=False`), initialized from the model's original training configuration. References are letterboxed before CLIP preprocessing to preserve the whole head/ears. Reference strength is controllable. This is image conditioning, not an identity guarantee; quality requires viewing actual GPU output. Both SDXL tokenizer context windows are checked before inference; oversized positive or negative prompts fail with `prompt_too_long` rather than silently truncating.

Start with reference strength `0.45`, guidance scale `4.5`, and `30` steps for a natural human or pet portrait. Lower reference strength if the original background or crop carries into the result; raising it can copy more of the original scene along with subject details. Inspect the output before accepting it.

Use `generation_mode="text"`, `subject_type="human"`, and `references=[]` to create a fictional human from the written brief without a source photo. This runs genuine SDXL text-to-image with IP-Adapter unloaded and no image conditioning; returning to reference mode restores the audited adapter and image encoder. `generation_mode="reference"` is the default and requires 1–3 images. Receipts record mode, reference count and whether the adapter was active. A fictional prompt does not guarantee that a generated person resembles nobody or establish copyright rights; review the result before using it.

`python -m image_worker download` downloads only the immutable safetensors/config/tokenizer inventory in `model-lock.json` and verifies each byte hash. `serve` loads only local files with safetensors and remote-code execution disabled, then binds `127.0.0.1:8877`. All routes require the session Bearer token from `AIFLOW_IMAGE_WORKER_TOKEN` (32+ ASCII bytes); token values are never persisted or printed. Use a separately audited tunnel to connect AIFlow.

The worker retains the exact reviewed Colab Torch 2.11.0+cu128 / TorchVision 0.26.0+cu128 pair under a narrow documented exception for GHSA-rrmf-rvhw-rf47. It never invokes Torch JIT/compile or loads pickle/custom model code. Other runtime versions fail closed pending a fresh review. The T4 profile keeps FP16 weights on the GPU, uses safe float32 VAE decoding in 512px tiles, one GPU execution thread and batch size one. This avoids handing the 5 GB UNet back to a small Colab host at decode. Startup/job diagnostics print only component dtype/device/parameter bytes, process RSS and GPU memory; generation receipts record the profile and peak VRAM. Actual fit and image quality require a GPU run.

Health is `GET /v1/health` (API version `1`, persistent worker UUID, immutable base-model revision). Submit `POST /v1/images/jobs` with a UUID `request_id`, generation mode, `human|pet` subject, text prompt, dimensions, seed, steps, guidance, reference strength and 1–3 `{mime,data,sha256}` references (or `references=[]` for a human in text mode). `GET /v1/images/jobs/{job_id}` returns persisted status and, on success, base64 PNG with a verified hash and generation provenance.

Job IDs equal request IDs. Identical retries reuse the persisted job; changed input with the same ID returns 409. At most three jobs are pending, with one generating. The manifest is atomically replaced and contains no token or raw reference bytes. Completed output is a separately stored PNG. Restart marks queued/running jobs `failed/interrupted`; regeneration requires a fresh request ID. `/content` storage lasts only the Colab runtime: configure a trusted durable data folder before starting if reconnection across runtime resets is needed.

For a genuine GPU smoke without a tunnel: `python -m image_worker smoke --request /content/request.json --output /content/result.png`. It writes a PNG and JSON receipt containing actual output SHA256, model/adapter revisions, settings and hardware; no fake production engine exists. Local API tests inject a test-only engine and do not prove GPU generation or image quality.
